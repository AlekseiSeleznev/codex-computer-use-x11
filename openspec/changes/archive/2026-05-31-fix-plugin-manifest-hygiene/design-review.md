## Design Summary

- Implementation removes two tracked backup files, adds a `*.bak.*` ignore rule, and leaves canonical OpenSpec configuration intact.
- Installer metadata remains generated by `scripts/install-codex-plugin.sh`; no new template or runtime boundary is introduced.
- Manifest copy uses grouped descriptions of the full current `x11_*` surface instead of repeating stale six-tool wording.
- Regression coverage extends the existing temporary `CODEX_HOME` installer test and uses Git checks for repository hygiene.

## Question Loop

1. **Question:** Does broad `*.bak.*` ignore conflict with any existing tracked fixture or release artifact naming convention?
   - **Recommended answer:** No; use broad ignore.
   - **Rationale:** `git ls-files` only showed the two accidental `openspec/config.yaml.bak.*` files for this pattern, and future intentional fixtures can be force-added if needed.
   - **Resolution:** Repository inspection resolves this; no user decision required.

2. **Question:** Should installer tests compare the manifest long description against every MCP tool name from `src/mcp.rs`?
   - **Recommended answer:** No; assert corrected homepage plus representative current groups/tools and absence of stale owner/six-tool-only wording.
   - **Rationale:** `tools/list` and README already own exhaustive tool enumeration. Coupling marketing text to every exact tool name would make harmless copy edits noisy while not improving runtime safety.
   - **Resolution:** Keep focused metadata assertions.

## Design Findings

- No conflict with `CONSTITUTION.md`, `ARCHITECTURE.md`, or in-force ADRs was found.
- Verification is feasible locally with OpenSpec validation, focused installer/git checks, and root project checks.
- The design correctly leaves behavioral findings 2.1 and 2.2 out of scope.
- No external systems or secret files are required.
